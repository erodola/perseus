# Table numbers, 2026-10-19

End-to-end walls of the encrypted runs on one NVIDIA RTX PRO 6000 Blackwell Server Edition (96 GB, driver 595.58),
host 2 x Xeon 6960P, CUDA 13.2, n32 chain, 128-bit keys. Every number is the run's own SUMMARY line, never rescaled.
Each run is one GPU with its host threads and memory on that GPU's NUMA node (GPU 0: node 1, memory 1,2; GPU 4: node 4,
memory 3,4,5). The commands are `scripts/repro/*.sh`, one per model.

The README's tables (`assets/paper-tables.tex`) show the warm-up rows for BERT and GPT-2 prefill, as the paper does. They

(21.1 s/token at a 512 context) is the paper's measurement and was not re-run on this build.

Accuracy, against the float64 models:
- Llama: top-1 124-127 of 128, median KL 5.1-5.6e-5.
- BERT: agrees with the float64 label, KL <= 1e-9.
- GPT-2 prefill: top-1 125 of 128, median KL 4.4-4.6e-4.
- GPT-2 decode: top-1 14-16 of 16. Every miss is a rank-1 near-tie, max KL <= 2e-3.
- ViT: top-1 and top-5 4 of 4.

## Protocol
- Excluded from every wall: key generation, weight encoding, encryption of the input, decryption of the output.
- **Llama** times its second pass. An untimed warm-up on another text window comes first, so masks and block-0 setup
  are not in the wall (the plan sets PF_WARMUP=1).
- **BERT and GPT-2 prefill** are cold: the wall includes block-0 first-use setup (about 2.1 s for BERT and 3.3 s for
  GPT-2: PCMM key-switch keys, mask encodes, PCMM precompute). With BERT_WARMUP=1 / GPT2_PF_WARMUP=1 they follow Llama's
  protocol: 38.4 s and 33.9 s on 10-19, measured on the pre-merge build.
- **GPT-2 decode** reports the steady tokens (position 1 on). Token 0 fills the caches.
- **ViT** reports the median of the 4 image walls. The first image builds the caches.

## Configuration
Every switch rides in the plan's `runtime=` line. No environment file is needed beyond `scripts/local_env.sh`.
- Plans:
  - `bootstrap_placements/llama31_8b_prefill_python_n32_pr2s12456e2r0sme2`
  - `bert_base_python_n32_cc2`
  - `gpt2_prefill_python_n32_blocked`
  - `gpt2_decode_python_n32`
  - `vit_base_224_python_n32_cc3`
- `plan_rot_steps.json` in a plan dir lists the rotation keys its graph uses, so only those load. Without it, the
  Llama prefill loads every key and runs at 128-130 s.
- Defaults that carry these numbers:
  - batched PCMM finishes: `PF_PCMM_BATCH=4`, `PF_PCMM_BATCH_DROPS=1`
  - L2 discard of dead NTT scratch: `FIDESLIB_DISCARD_SCRATCH=1`
  - anonymous pinned host buffers: `FIDESLIB_PINNED_ANON=1`

## Measuring
- Run one model per GPU. Two concurrent runs on different GPUs can stall each other for about 3 s: a process that
  releases ~100 GB of pinned memory holds the driver lock while the other one allocates. The BERT, GPT-2 and ViT
  numbers above are solo runs, or concurrent runs without such a stall block.
- Keep the GPU's NUMA node free of other large jobs. Proactive memory compaction (kcompactd) on a fragmented node used
  to slow a run by 5-10%. The anonymous pinned buffers keep it idle.
- Environment of these runs:
  - `PERSEUS_DATA` and `HF_HOME` point at the model caches.
  - BERT needs scipy for its float64 reference.
  - ViT runs on `scripts/repro/data/vit_eurosat` (4 pre-normalized EuroSAT images).
